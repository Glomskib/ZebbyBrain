Turn on the Ask Zebby UI (Vite flag)

In Replit → Secrets (and also in Deployment → Environment if using Deployments), add:

VITE_FF_RAG=true


Then restart / redeploy (Vite only reads VITE_* at build-time).

Quick check

Open: /api/meta/config → ff_rag_frontend should now be true (or "true" depending on your code).

In the app, Ask Zebby should appear in the nav, and /ask-zebby should load.

2) Configure Firebase (mobile auth)

In Firebase Console → Project settings → Service accounts → Generate new private key.
From the JSON you download, copy these to Replit → Secrets (and Deployment env):

FIREBASE_PROJECT_ID=<value of project_id in JSON>
FIREBASE_CLIENT_EMAIL=<value of client_email in JSON>
FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n<contents with \n between lines>\n-----END PRIVATE KEY-----\n"


⚠️ Keep the \n escapes in FIREBASE_PRIVATE_KEY.
Then restart / redeploy.

Quick check

/api/meta/config → firebase_configured should be true.

3) Allow mobile/web origins (CORS)

In Replit → Secrets (and Deployment env) add:

ALLOWED_ORIGINS=https://preview.flutterflow.app,https://app.zebbysworld.com,capacitor://localhost,ionic://localhost,http://localhost:5173


(Include your actual deployed domain too, e.g., https://<your-replit-domain>.replit.app.)
Restart / redeploy.

Quick check

/api/meta/config → cors_allowed_origins should list your origins (not just “localhost-only”).

One-minute verification
# Config snapshot
curl -s https://<your-domain>/api/meta/config | jq

# Health
curl -s https://<your-domain>/api/rag/health

# Motivation
curl -s https://<your-domain>/api/motivation


Expected in config after fixes:

{
  "ok": true,
  "ff_rag_backend": true,
  "ff_rag_frontend": true,
  "cors_allowed_origins": ["https://preview.flutterflow.app","..."],
  "firebase_configured": true
}

If Ask Zebby still doesn’t show

Make sure you set VITE_FF_RAG=true in both Workspace Secrets and Deployment Env.

Restart/redeploy (Vite must rebuild).

In client code, confirm you’re using import.meta.env.VITE_FF_RAG (not process.env).

Do a hard refresh / incognito to bust cache.

Optional sanity in the client:

// client/src/lib/flags.ts
export const FF_RAG =
  (import.meta.env.VITE_FF_RAG ?? "false").toString().toLowerCase() === "true";
console.log("FF_RAG(frontend) =", import.meta.env.VITE_FF_RAG);


That’s it—flip those three switches, redeploy, and your Kickstarter flow will work end-to-end:

Positive message on load

Ask Zebby visible and answering with sources

Counter decreases; upgrade banner at 0

Stripe checkout opens from the banner
