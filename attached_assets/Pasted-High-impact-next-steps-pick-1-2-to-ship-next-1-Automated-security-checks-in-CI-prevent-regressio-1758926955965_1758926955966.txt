High-impact next steps (pick 1–2 to ship next)
1) Automated security checks in CI (prevent regressions)

Run header tests, auth tests, and npm audit on every PR.

Block merges if someone reintroduces req.body.userId in billing.

Example GitHub Actions job

name: security-ci
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - run: npm ci
      - run: npm run build --workspaces=false || true
      - run: npm test
      - run: npm audit --omit=dev --audit-level=high
      - name: forbid-billing-userid
        run: "! grep -R \"req.body.userId\" server/src/routes/billing.ts"

Keep your strict CSP, but run a Report-Only twin for a week to surface any blocked resources.

Server

3) Secrets rotation helper + health alarm

Quarterly rotation is policy; make it trivial and observable.

Require env (fail fast)

const requireEnv = (k: string) => {
  const v = process.env[k]; if (!v) throw new Error(`Missing env: ${k}`); return v;
};
export const SESSION_SECRET = requireEnv("SESSION_SECRET");
export const STRIPE_WEBHOOK_SECRET = requireEnv("STRIPE_WEBHOOK_SECRET");


Expose status for uptime monitors

app.get("/api/meta/status", (_req,res) => {
  const key = process.env.STRIPE_SECRET_KEY || "";
  res.json({
    ok: true,
    stripe: {
      configured: Boolean(key && process.env.STRIPE_PLUS_PRICE_ID),
      mode: key.startsWith("sk_live_") ? "live" : key.startsWith("sk_test_") ? "test" : "unknown",
    }
  });
});


Point your monitor to /api/meta/status and alert if configured:false or mode:unknown.
