Fixes Needed
1. Enable Ask Zebby

In Replit → Secrets (and also in the Deployment env) add:

VITE_FF_RAG=true


Then Restart / Redeploy the app.
⚠️ Important: Vite only exposes VITE_ vars at build time, so a restart is mandatory.

✅ After redeploy, check logs → you should see:

FF_RAG=true


Then /ask-zebby will appear in the nav.

2. Configure Firebase (for mobile auth)

Create a Firebase service account in your Firebase Console → Project Settings → Service Accounts → Generate New Key.

In Replit Secrets, add:

FIREBASE_PROJECT_ID=your-firebase-project-id
FIREBASE_CLIENT_EMAIL=service-account@your-project-id.iam.gserviceaccount.com
FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"


(Escape newlines as \n).

Add your allowed mobile/web origins:

ALLOWED_ORIGINS=https://preview.flutterflow.app,https://app.zebbysworld.com,capacitor://localhost,ionic://localhost,http://localhost:5173


Restart / Redeploy again.

✅ Verification Steps

Check logs

Confirm startup logs show your ALLOWED_ORIGINS.

Confirm FF_RAG=true.

Ask Zebby nav

/ask-zebby should now appear in your menu.

Visiting /ask-zebby directly should render the page even if the link is hidden.

Firebase auth test (optional but nice)

Create a test Firebase user.

Exchange email/pass for ID token:

curl -s "https://identitytoolkit.googleapis.com/v1/accounts:signInWithPassword?key=YOUR_FIREBASE_WEB_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"email":"test@example.com","password":"yourpass","returnSecureToken":true}'


Use the .idToken in:

curl -i -s -X POST https://<your-app>/api/rag/answer \
  -H "Authorization: Bearer $ID_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"question":"What are common EDS symptoms?","window":"30d"}'


Expect 200 OK + X-Queries-Left.
