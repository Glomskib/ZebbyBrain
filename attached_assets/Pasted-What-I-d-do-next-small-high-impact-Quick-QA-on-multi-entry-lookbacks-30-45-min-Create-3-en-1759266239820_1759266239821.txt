1) My Herd — Manual Reach-Out

DB (migrations)

herd_alert (id, user_id, recipient_user_id, status 'pending'|'sent'|'canceled', created_at, sent_at, canceled_at, message TEXT, window_expires_at TIMESTAMPTZ)

Index (recipient_user_id, status).

API

POST /api/herd/reach-out → body: { recipients: string[], message?: string }

Creates pending rows; sets window_expires_at = now()+10m.

Returns a cancel_token.

POST /api/herd/cancel → { cancelToken } → sets all matching pending to canceled.

Background tick every minute:

Sends email/in-app to recipients for pending rows whose window_expires_at <= now().

Marks as sent; writes minimal audit (no PHI in logs).

All responses: Cache-Control: no-store. Rate-limit reach-outs (e.g., 3/hour).

UI

Reach Out button (Home + My Herd page).

Dialog: select herd members (checkbox list), optional short message.

After submit: show “Alert pending — you can cancel within 10 minutes” with a cancel button and countdown.

Toast on send/cancel; link to recent alerts (audit list).

Acceptance

Pending visible with countdown; cancel prevents messages; sent items appear in audit; rate limit enforced.
