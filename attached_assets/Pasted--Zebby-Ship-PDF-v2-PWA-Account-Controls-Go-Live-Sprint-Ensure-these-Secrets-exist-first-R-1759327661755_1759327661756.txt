1) Clinician PDF v2 (server + client)

Endpoint GET /api/exports/pdf?v=2&from=&to=&tz=America/Chicago

Security: auth required; Cache-Control: no-store; no external calls while rendering.

Content:

Cover: logo/title, user initials (not full name), date range, generated timestamp.

Zebby Findings: reuse /api/ai/insights facts builder (non-diagnostic).

Trends: embed three PNG sparklines (pain avg, HR Δ, sleep hours). Generate server-side (node-canvas or lightweight chart util).

Entries: grouped by user’s TZ day; each entry shows local time, intensity, bodyPart/side, notes; stamps if present: weatherTempC, weatherText, HR (standing vs supine if you have it), hydration.

Budget: < 5 MB for 90 days; paginate internally if needed.

Errors: graceful “no data for range” section.

3) Account Controls (server + client)

Delete Account (with 7-day undo)

DB: add users.deleted_at TIMESTAMPTZ + users.delete_token (UUID).

API:

POST /api/account/delete → soft-delete, set deleted_at=now(); email a restore link (or show token in dev).

POST /api/account/undo-delete { token } → clears deleted_at.

Purge worker (cron) runs daily: permanently delete users with deleted_at < now()-7d (cascade or scripted scrub across tables; keep audit but no PII).

UI: Settings → “Delete account” with clear explainer & countdown banner if scheduled.

Backup / Restore (encrypted)

Export: GET /api/account/backup → authenticated, generates zip (CSV/JSON per table) encrypted with a passphrase (e.g., libsodium secretbox or AES-GCM). Cache-Control: no-store.

Restore: POST /api/account/restore → upload encrypted zip + passphrase; schema-safe re-import for current user only (no cross-user IDs).

UI: Settings → Data → “Download backup” / “Restore from backup”.

Tests

Delete → undo within window works; purge after 7 days (simulate) removes data.

Backup → restore round-trip yields identical row counts for the user; rejects wrong passphrase.
