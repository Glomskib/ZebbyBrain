3) Week-Active Cron (server)

New job server/src/jobs/weekActive.ts:

Daily run (guarded by ENABLE_CRON=true).

Find referred users whose first 7 days ended yesterday, count distinct logging days (symptoms/vitals/sleep/hydration ≥ 5).

If not already credited: insert rewards_ledger +250 (reason='active_week') and referral_events type='week_active'.

Wire a small scheduler in server/src/index.ts (or your cron runner):

if (process.env.ENABLE_CRON === "true") {
  const HOUR = 1000 * 60 * 60;
  setInterval(() => {
    const now = new Date();
    if (now.getUTCHours() === 2) runWeekActive().catch(console.error);
  }, HOUR);
}


Logs must be minimal, no PII.

4) Tests (must pass)
4.1 Groups Access & Rate Limits

User age 17 → POST /api/groups/:adultId/join → 403 with helpful message.

User gender mismatch for gendered group → 403.

Diagnosis group without tag → 403.

Posts >6/h → 429; Comments >20/h → 429; Reactions >60/h → 429.

4.2 Posting/Comments/Sanitization

Posting <script>alert(1)</script> yields sanitized body (no HTML).

Line breaks preserved in render (server returns plain text; client renders with <br/> safely).

4.3 Reactions & Reports

React twice with same emoji returns idempotent state (no duplicates).

Reporting returns 200 and inserts a row.

4.4 Referrals & Rewards

GET /api/referrals/code returns a 6-char code; second call returns same code.

Applying code at signup attaches referrer; creates signup event and +100 in ledger (unique index prevents duplicates).

Simulated cron (invoke function) credits +250 active_week once; balance matches sum; history paginates.

5) Security/Privacy (don’t regress)

All Group/Referral/Rewards endpoints require auth and return Cache-Control: no-store.

Logs do not include post/comment text or emails.

CSP/Helmet intact; no inline HTML rendering from user content.

Rate-limit middleware is IPv6-safe and user-ID keyed.
