Turn on the Ask Zebby UI (Vite flag)

In Replit → Secrets (and Deployment env):

VITE_FF_RAG=true


Then restart / redeploy. (Vite only reads VITE_* at build time.)

Optional sanity in code (client):

// client/src/lib/flags.ts
export const FF_RAG =
  (import.meta.env.VITE_FF_RAG ?? "false").toString().toLowerCase() === "true";


Use it to show the nav item, but keep the route public so QA can hit it directly:

{FF_RAG && <Link to="/ask-zebby">Ask Zebby</Link>}
<Route path="/ask-zebby" element={<AskZebbyPage />} />

2) Wire Firebase for mobile auth

Add these Replit secrets (and Deployment env), then restart:

FIREBASE_PROJECT_ID=your-project-id
FIREBASE_CLIENT_EMAIL=service-account@your-project-id.iam.gserviceaccount.com
FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"


(Keep the \n escapes.)

3) Allow your mobile/web origins (CORS)

Add:

ALLOWED_ORIGINS=https://preview.flutterflow.app,https://app.zebbysworld.com,capacitor://localhost,ionic://localhost,http://localhost:5173


Restart so the server logs the parsed origins.

Paste-this “finalizer” snippet (optional but handy)

Add a tiny, safe config endpoint + boot logs so you can verify without digging through code:

server/meta/config.ts

import { Router } from "express";
export const configMeta = Router();

function bool(v?: string) {
  return (v ?? "").toString().toLowerCase() === "true";
}

const parsedOrigins = (process.env.ALLOWED_ORIGINS || "")
  .split(",")
  .map(s => s.trim())
  .filter(Boolean);

console.info("[BOOT] FF_RAG(frontend):", process.env.VITE_FF_RAG);
console.info("[BOOT] CORS allowed origins:", parsedOrigins);

configMeta.get("/meta/config", (_req, res) => {
  res.json({
    ok: true,
    ff_rag_frontend: bool(process.env.VITE_FF_RAG),
    cors_allowed_origins: parsedOrigins,
    // note: we DO NOT expose any secrets or private keys here
    firebase_configured: Boolean(
      process.env.FIREBASE_PROJECT_ID &&
      process.env.FIREBASE_CLIENT_EMAIL &&
      process.env.FIREBASE_PRIVATE_KEY
    )
  });
});


Mount it:

// server/index.ts
import { configMeta } from "./meta/config";
app.use("/api", configMeta);


Now you can visit /api/meta/config and see:

{
  "ok": true,
  "ff_rag_frontend": true,
  "cors_allowed_origins": ["https://preview.flutterflow.app", "..."],
  "firebase_configured": true
}

Quick verification script (copy/paste)
# 1) Check flags / CORS allowlist quickly
curl -s https://<your-app>/api/meta/config | jq

# 2) Health
curl -s https://<your-app>/api/rag/health

# 3) Ask Zebby page visible (after VITE_FF_RAG=true + redeploy)
open https://<your-app>/ask-zebby   # or just navigate in the UI

# 4) Firebase token flow (optional but nice)
# get a Firebase ID token via REST, then:
curl -i -s -X POST https://<your-app>/api/rag/answer \
  -H "Authorization: Bearer $ID_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"question":"What are common EDS symptoms?","window":"30d"}'
# Expect 200 and header: X-Queries-Left: <n>

Common “why is Ask Zebby still hidden?” causes

Forgot to set in Deployment env. Set VITE_FF_RAG=true in both Workspace and Deployment, then redeploy.

Didn’t restart. Vite requires a rebuild to inject VITE_*.

Using process.env in client. Must be import.meta.env.VITE_FF_RAG.

Browser cache. Hard refresh or open a private window.
